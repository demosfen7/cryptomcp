## 1. Что сделано по этапам

<!-- Каркас · шаблоны без ИИ · Claude · документация. Коротко, без пересказа диффа. -->

### Этап 1 · каркас

- Добавлен отдельный контейнер `cryptomcp-bot` и модуль `cryptomcp.bot` с
  long polling `getUpdates`. Healthcheck проверяет время последнего успешного
  ответа Telegram, а не существование процесса.
- Доступ централизован в одной функции: пустой `BOT_ALLOWED_USER_IDS` никого
  не допускает; `/id` работает для всех; `/start` сохраняет личный chat id
  владельца для будущего утреннего обзора.
- Состояние бота живёт в отдельном `bot.sqlite` рядом с архивом. В
  `market.sqlite` ничего не записывается.
- Добавлена проверочная команда `python -m cryptomcp.bot render`; её реальные
  шаблоны появятся на следующем этапе.

### Этап 2 · шаблоны без ИИ

- Список наблюдения берёт эпизоды и последние строки скана из `market.sqlite`,
  стакан — объект `orderbook.build_order_book`, итог наблюдения —
  `orderbook_watch.classify_liquidity`. Текстовые выдачи MCP-инструментов не
  разбираются и в Telegram не пересылаются.
- Добавлены шаблоны списка, стакана, итогов наблюдения и ручных находок;
  запрещённые технические слова проверяются вместе с их длиной в тестах.
- Наблюдение, начатое ботом, принадлежит его процессу и присылает итог в чат
  запуска. После рестарта владелец получает сообщение о прерывании с кнопкой
  повторного запуска.
- Уведомления сборщика сохранили свой текст и получили компактные inline
  кнопки для вошедших и подтверждённых монет; ошибка Telegram по-прежнему не
  поднимается наружу.
