## Зачем

Сейчас бот в Telegram только сообщает: сборщик пишет в группу, какие монеты
вошли в список наблюдения и вышли из него. Чтобы разобраться в монете,
владелец идёт в Claude и спрашивает словами. Задача — дать ему **готовые
кнопки сценариев прямо в Telegram**: частые вопросы одним нажатием, под
уведомлением — «разобрать эту монету».

Требование владельца, на котором держится всё задание: **не утонуть в куче
непонятных цифр**. Выдача инструментов пишется для модели — длинная, с
перцентилями и ATR (разбор монеты — около 8 тыс. символов, снимок стакана —
11). Пересылать её в чат нельзя. Для этого `MOCKUPS.md`.

## Решения, принятые за вас

Обсуждены с владельцем. Не согласны — не меняйте молча, напишите в `REPORT.md`.

### Б1. Бот — третий контейнер, `cryptomcp-bot`

Не поток в сборщике: ошибка в разборе нажатия не имеет права стоить часа
невосстановимых деривативов (`PROJECT-RULES.md`, «Процессы»). Не поток в
MCP-сервере: бесконечный цикл `getUpdates`, упавший или зависший на сети, не
должен утянуть за собой ответы Claude в чате, а у сервера и бота разные
признаки живости.

Тот же образ, что у сервера и сборщика, другая команда запуска
(`python -m cryptomcp.bot`), том `cryptomcp_data` смонтирован так же. Свой
healthcheck по смыслу: «когда бот последний раз успешно получил ответ
`getUpdates`», а не «жив ли процесс».

### Б2. Нажатия — long polling `getUpdates`, без webhook

Webhook потребовал бы публичного пути через общий Caddy, правки которого
затрагивают все шесть проектов на сервере. Long polling обходится без этого.
Токен тот же, что у уведомлений (`TELEGRAM_BOT_TOKEN`): отправлять сообщения
через него может и сборщик, и бот одновременно, а `getUpdates` читает только
бот.

### Б3. Доступ: только владелец, список расширяется настройкой

`BOT_ALLOWED_USER_IDS` — список Telegram user id через запятую. Нажатие или
команда от кого-то ещё — ответ «нет доступа, ваш id N» и запись в лог, больше
ничего. Команда `/id` работает для всех: так владелец узнаёт свой id, не
заглядывая в логи. Проверка — по `from.id` нажавшего, **не** по чату: в группе
кнопки видят все участники.

Пустой список — бот не отвечает никому (безопасное умолчание), кроме `/id`.

Позже владелец хочет открывать доступ другим, если анализ окажется хорошим.
Поэтому доступ — одной функцией, а не проверками, разбросанными по
обработчикам.

### Б4. Шаблоны без ИИ строятся из данных, а не из текста инструментов

Разбирать регулярками текстовую выдачу `get_watchlist` или `get_order_book`
запрещено: первая же правка формулировки в инструменте молча сломает бота.
Брать структурированные данные там, откуда их берут сами инструменты:
список — из тех же функций хранилища, что `server.get_watchlist`; стакан —
`orderbook.build_order_book`; итог наблюдения — `orderbook_watch.classify_liquidity`.
Если нужной функции, возвращающей данные, нет, — выделите её из инструмента,
не меняя текст его выдачи (тест на неизменность выдачи обязателен).

### Б5. Claude: Sonnet 5 через Anthropic API, инструменты вызываются в процессе

- Модель `claude-sonnet-5`. Зависимость — официальный SDK `anthropic`
  (единственная новая зависимость, объяснить в отчёте версию).
- Ключ — `ANTHROPIC_API_KEY` из окружения. Нет ключа — кнопки 🧠 отвечают
  «Claude не настроен», шаблоны работают. Это штатный режим, а не ошибка.
- **Инструменты передаются Claude как client-side tools и исполняются прямо в
  процессе бота** вызовом тех же асинхронных функций, что зарегистрированы в
  `server.py`. Не через MCP по HTTP: лишний сетевой круг и OAuth ради того же
  вызова функции.
- **Каждой кнопке — только её инструменты** (таблица в `MOCKUPS.md` 4.3), а не
  все 17: описания всех инструментов — 16.5 тыс. символов, и они оплачиваются
  в каждом запросе.
- Системная инструкция — `MOCKUPS.md` 4.1. Описания инструментов и системная
  инструкция помечаются `cache_control` (prompt caching): внутри одного
  сценария идут 2–3 запроса, и повтор префикса стоит 10% цены.
- Цикл вызовов инструментов ограничен: не больше 6 раундов и `max_tokens`
  2000 на ответ. Упёрлись — ответить тем, что есть, и сказать об этом.
- Пока идёт ответ — сразу сообщение «⏳ Разбираю ID…», которое затем
  редактируется в ответ. На нажатие кнопки ответить `answerCallbackQuery`
  немедленно, иначе у пользователя крутится индикатор.
- Одновременно — один запрос к Claude на пользователя. Повторное нажатие во
  время разбора — «уже разбираю, подождите».

### Б6. Деньги: потолок $1 в день и стоимость под каждым ответом

Решение владельца: **$1 в день, и после каждого ответа Claude писать его
стоимость**.

- Стоимость — **по фактическому `usage` каждого ответа API** (обычный ввод,
  запись в кеш, чтение из кеша, вывод), суммой по всем раундам сценария.
- Цены — константы, снятые со страницы
  `platform.claude.com/docs/en/about-claude/pricing` 17.09.2026, с датой в
  комментарии. Sonnet 5, $ за миллион токенов: ввод 2, запись в кеш (5 мин)
  2.50, чтение из кеша 0.20, вывод 10.
- Учёт — таблица в своей базе бота `bot.sqlite` (рядом с архивом в том же
  томе, пишет только бот): время, кнопка, монета, токены по видам, стоимость.
- Лимит — `BOT_DAILY_BUDGET_USD`, по умолчанию 1.0, день — календарный в
  `BOT_TIMEZONE` (по умолчанию `Europe/Berlin`). **Проверка до запуска
  сценария**: если потрачено + оценка сценария больше лимита — отказ по
  шаблону `MOCKUPS.md` 4.5. Оценка — константа 0.10 $ на сценарий (замер ниже
  даёт 4–7¢; запас на длинный ответ). Итог может чуть превысить лимит одним
  сценарием — это допустимо, но не больше.
- Подпись стоимости — `MOCKUPS.md` 4.4.
- Утренний обзор, присланный ботом сам, тратит из того же лимита.

### Б7. Утренний обзор — и по кнопке, и сам

`BOT_MORNING_TIME` (по умолчанию `08:00`) в `BOT_TIMEZONE`. Отправляется в
личный чат владельцу — первому id из `BOT_ALLOWED_USER_IDS`, который хотя бы
раз написал боту `/start` (без этого Telegram не даёт писать человеку первым;
запомнить chat id в `bot.sqlite`). Пропущенное утро (бот лежал) не
досылается: вчерашний обзор никому не нужен. Пустой `BOT_MORNING_TIME` —
выключено.

### Б8. Наблюдение за стаканом из бота тикается в процессе бота

Кнопка «Понаблюдать» вызывает ту же функцию старта сессии, что и
`start_order_book_watch`, — тикер оказывается задачей процесса бота, а не
MCP-сервера. Это нормально: допуск по весу считается по общей базе
`order_book_watch.sqlite`, а не по процессу, так что сессии бота и сервера
делят один потолок. Зато бот знает, когда сессия кончилась, и **сам присылает
итог** в тот чат, где её запускали (`MOCKUPS.md` 3.4).

Сессия не переживает перезапуск бота — ровно как у сервера. При старте бот
находит свои незавершённые сессии (запомнить их id и чат в `bot.sqlite`) и
пишет: «наблюдение за ARB прервано перезапуском, запустить заново?» с кнопкой.

Сессии, запущенные из Claude через MCP, бот не трогает и итогов по ним не
шлёт.

### Б9. Кнопки под уведомлениями добавляет сборщик

`notify.Telegram.send` получает необязательный `reply_markup` (inline
keyboard), `notify_watchlist` строит кнопки по монетам дельты (`MOCKUPS.md`
3.2). Отправка по-прежнему **никогда не поднимает исключение** и не роняет
прогон — это правило §4.24, оно в силе. Нажатия обрабатывает бот.

`callback_data` у Telegram — не больше 64 байт. Кодировать компактно
(`a:EULUSDT:1d:s`), тест на длину для самого длинного символа архива
обязателен: в архиве есть символ из китайских иероглифов (`币安人生USDT`), он
в UTF-8 длиннее, чем выглядит.

### Б10. Ввод монеты и текста

Основное место работы с ботом — личный чат. В группе у ботов обычно включён
режим приватности, и обычный текст до бота не доходит: там ввод — через ответ
на сообщение бота (`ForceReply`). Нажатия кнопок доходят в любом случае.

### Б11. Проверочная команда без Telegram

`python -m cryptomcp.bot render <сценарий> [монета]` — печатает в консоль
ровно тот текст, который ушёл бы в Telegram, **и стоимость**, если сценарий
через Claude. Без токена Telegram. Нужна для живой приёмки: и вам, и приёмке
на сервере, где ключ Anthropic будет, а нажимать кнопки в Telegram приёмка не
может.

## Границы

**Можно менять**, и это часть задачи:

- `docker-compose.yml` — добавить сервис `bot`;
- `.github/workflows/deploy.yml` — **только** строку `printf ... > .env`:
  дописать `ANTHROPIC_API_KEY` и `BOT_ALLOWED_USER_IDS` из секретов GitHub.
  `.env` перезаписывается при каждом выкате целиком, и переменная, не
  попавшая в эту строку, на сервере не появится;
- `cryptomcp/notify.py` — `reply_markup` и кнопки (Б9);
- `pyproject.toml` — зависимость `anthropic`.

**Нельзя:**

- `SQUEEZE_FORMULA_VERSION` и схему `market.sqlite`;
- текст выдачи существующих 17 инструментов (бот — новый читатель, а не повод
  переписать старых);
- шаги workflow, кроме строки с `.env`; Caddy и всё вне `/opt/cryptomcp`;
- `app.py` и OAuth;
- раздел «Состояние» в `PLAN.md`.

**Секреты.** Ни ключ Anthropic, ни токен Telegram не попадают в код, тесты,
логи и отчёт. Ключ и id владелец положит в секреты GitHub сам.

## Тесты

Сеть в тестах запрещена: поддельные Telegram и Anthropic-клиент.

1. Доступ: чужой `from.id` — «нет доступа, ваш id N», сценарий не запускается,
   запросов к Claude нет; пустой список — отказ всем; `/id` работает для всех.
2. Шаблоны: для каждого шаблона без ИИ — тест на **текст** сообщения на
   фикстурах, собранных из живой выдачи (как у приёмки стакана): нет
   запрещённых слов из `MOCKUPS.md` 1.3, длина до 4096, легенда только для
   присутствующих меток.
3. `callback_data` не длиннее 64 байт на самом длинном символе, включая
   `币安人生USDT`.
4. Учёт: стоимость из поддельного `usage` с кешем совпадает с ручным расчётом
   по ценам; сумма раундов; день в `BOT_TIMEZONE`.
5. Лимит: при потраченных 0.95 $ сценарий отклоняется **до** запроса к Claude.
6. Claude без ключа — «Claude не настроен», шаблоны работают.
7. Каждой кнопке 🧠 передаётся только её набор инструментов.
8. Цикл инструментов останавливается на 6 раундах.
9. Сборщик: уведомление с кнопками уходит с `reply_markup`; ошибка отправки
   по-прежнему не поднимает исключение; текст уведомления не изменился.
10. Выдача существующих инструментов, из которых выделены функции данных,
    не изменилась ни на символ.
11. Итог наблюдения: по окончании сессии уходит сообщение в чат запуска; при
    старте бота незавершённые сессии дают сообщение «прервано перезапуском».
12. Утренний обзор: в `BOT_MORNING_TIME` один раз, не досылается задним числом.

## Живая приёмка — в `REPORT.md`

Без ключа Anthropic (он появится только на сервере):

- проверочной командой (Б11) — текст **всех** шаблонов без ИИ на живых данных
  как есть: список, стакан (ликвидная и тонкая монета), итог живого
  наблюдения ARBUSDT на 2–3 минуты, мои находки;
- длина каждого в символах и отметка, есть ли запрещённые слова.

С ключом, если он у вас есть для разработки, — не обязателен:

- разбор одной монеты из списка наблюдения — текст и **фактическая стоимость
  по `usage`** против оценки из этого файла.

Приёмка на сервере повторит всё это с боевым ключом.
